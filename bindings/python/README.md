# whiteout — native Python bindings

pybind11-based Python extension exposing the same C++ API as the WASM
build. Source for the `whiteout` extension lives in:

- `module.cpp` — top-level `PYBIND11_MODULE`, parser/writer wrappers, and
  the in-memory virtual filesystem for M2.
- `mdx_bindings.cpp`, `m2_bindings.cpp`, `m3_bindings.cpp` —
  AUTOGENERATED. Do **not** edit by hand. They're produced from the
  annotated C++ headers under `include/whiteout/...` by
  `tools/codegen/emit_pybind.py`.

## Build

```pwsh
scripts\build-python.ps1
```

That regenerates the four `*_bindings.cpp` files (`python -m
tools.codegen.codegen <m> --backend pybind11`), configures CMake with
`-DWHITEOUT_BUILD_PYTHON_BINDINGS=ON`, builds, and stages the resulting
`.pyd` into `bindings/python/whiteout.cp<ver>-<plat>.pyd`.

## Use

```python
import sys
sys.path.insert(0, 'bindings/python')
import whiteout as w

# MDX  -- fields/methods are snake_case; constants are UPPER_SNAKE_CASE
mdl = w.mdx.Parser().parse(open('model.mdx', 'rb').read())
print(f"{mdl.model_name} v{mdl.version}: {len(mdl.geosets)} geosets")
re_encoded = w.mdx.Writer().write(mdl)

# M3 -- same API, dedicated submodule
m3_model = w.m3.Parser().parse(open('model.m3', 'rb').read())

# M2 -- multi-file: provide siblings via in-memory FS
fs = w.InMemoryFileSystem()
fs.add_file('models/character.m2',     open('character.m2',     'rb').read())
fs.add_file('models/character00.skin', open('character00.skin', 'rb').read())
m2 = w.m2.Parser().parse(fs, 'models/character.m2')

# Textures -- BlpParser/PngParser/etc. live at root for ergonomics
blp_bytes = open('texture.blp', 'rb').read()
tex = w.BlpParser(w.BlpParseMode.LENIENT).parse(blp_bytes)
print(f"{tex.width()}x{tex.height()}")
png_bytes = w.PngWriter().write(tex)

# Sentinels (UPPER_SNAKE)
print(w.mdx.NO_PARENT, w.mdx.MULTIPLE_GEOSETS)
```

## Structure of the Python module

- `whiteout.mdx.*` — Warcraft III MDX/MDL types
- `whiteout.m2.*`  — World of Warcraft M2 types
- `whiteout.m3.*`  — StarCraft II / HotS M3 types
- `whiteout.{Vector2f,Vector3f,Vector4f,Quaternion}` — shared math types
- `whiteout.{BlpParser,PngParser,Texture,...}` — texture surface

Every model type is a regular Python class: construct with `()`, set
attributes directly, vector members are list-like (`append`, indexing,
`len`).

## NumPy zero-copy access

Vectors of primitive types (`u8`/`u16`/`u32`/`f32`/...) and of the
standard math types (`Vector2f`, `Vector3f`, `Vector4f`, `Quaternion`,
`ColorBGRA`) implement the buffer protocol, so `np.asarray(vec)` returns
a view that shares memory with the underlying C++ `std::vector` —
**no copy**, mutations propagate back.

```python
import numpy as np

# 1D buffer for primitive vectors: shape = (N,)
keys = np.asarray(track.keys)             # dtype=float32
keys[:] *= 2                              # writes through to C++

# 2D buffer for math-struct vectors: shape = (N, components)
pivots = np.asarray(model.pivot_points)   # shape=(N, 3), dtype=float32
tangents = np.asarray(geo.tangents)       # shape=(N, 4), dtype=float32

# Bulk-fill from numpy: still need to push elements one-by-one (the
# numpy view is for *reading* / *mutating in place*, not resizing).
for row in coords:                        # coords: (N, 3) float32
    v = w.Vector3f()
    v.x, v.y, v.z = row
    model.pivot_points.append(v)
```

**Caveat — resize invalidates the view.** `append`/`extend`/`clear`
may reallocate the C++ buffer, in which case the previously-acquired
numpy view points at freed memory. Re-acquire (`np.asarray(vec)`) after
any size-changing operation.

## Naming conventions

The pybind11 emitter follows PEP 8 — fields/methods are `snake_case`,
enum members and module-level constants are `UPPER_SNAKE_CASE`, classes
stay `PascalCase`. The Embind (JS) backend keeps `camelCase` to match JS
conventions, so identical C++ field names surface differently per
language:

| C++                          | Embind (JS)              | pybind11 (Python)            |
|------------------------------|--------------------------|------------------------------|
| `mdx::Bone`                  | `MdxBone`                | `whiteout.mdx.Bone`          |
| `m3::BlendMode::AlphaBlend`  | `M3BlendMode.AlphaBlend` | `m3.BlendMode.ALPHA_BLEND`   |
| `Sequence::intervalEnd`      | `seq.intervalEnd`        | `seq.interval_end`           |
| `Bone::geosetId`             | `bone.geosetId`          | `bone.geoset_id`             |
| `Parser::hasIssues()`        | `parser.hasIssues()`     | `parser.has_issues()`        |
| `Node::NO_PARENT` (constant) | `M.MdxNoParent`          | `mdx.NO_PARENT`              |
| enum value `None`            | `Foo.None`               | `Foo.NONE` (PEP 8 + keyword) |
| `Vector3f`                   | `Vector3f`               | `whiteout.Vector3f`          |

The `Mdx`/`M2`/`M3` prefixes are dropped on the Python side because each
type already lives in a submodule.

## Regenerating after a header change

Workflow is identical to the WASM bindings: annotate the C++ header in
`include/whiteout/...` with `/// @bind ...`, then run
`scripts\build-python.ps1`. The codegen reads the annotations via
libclang and produces fresh `*_bindings.cpp` files.

See `tools/codegen/README.md` for the annotation reference.
